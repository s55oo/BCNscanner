Add-ons — what's new

Add-onDescription
Green toggle indicators All control-bar toggle buttons — noP, noU, noX, noT, radar, tune and roto — light up bright green (glowing border and tinted background) when active, so armed/hidden state is visible at a glance. Clicking again turns the light off.
Tune filter bandwidth Every tune command now selects an explicit receiver filter instead of leaving the rig at its default. Default is 600 Hz, configured via RADIO_TUNE_BW in .env. Set it to 0 to restore the rig's own default filter.

Frequently asked questions

The roto button used to be hard to tell apart — how does it look now?

Armed state is unmistakable: bright green text and border with a soft green glow. Disarmed it looks like every other toggle button (grey). The colour change is instant on click, together with the "Rotor ON/OFF" toast.

Why did my rig switch to a 400 Hz filter when tuning?

It didn't choose it — that was your radio's default CW passband. Previously the scanner set the mode with passband 0, meaning "whatever the rig uses by default", and the TS-590SG defaults to 400 Hz on CW.

How do I change the tune filter bandwidth?
  1. Edit RADIO_TUNE_BW in the server's .env file (value in Hz).
  2. Apply with docker compose up -d.
  3. Next tune selects the mode (RADIO_TUNE_MODE) together with that passband.

Common values: 500/600 for CW beacon work, 2400 for SSB, 0 for rig default.

I clicked a bearing but nothing turned — what's wrong?

Check three things:

  1. Is the rotator enabled in .env (ROTATOR_ENABLED=yes)? The roto button is hidden otherwise.
  2. Is the button glowing green (armed)? Clicking works only while armed.
  3. Is the controller reachable? Amber italic azimuth readout means a command was sent but not confirmed yet; check docker logs -f bcnscanner-api.
Does the green roto state survive a page reload?

No — arming is deliberately a per-session safety measure. After a reload both tune and roto start disarmed so a stale open tab can never move hardware by accident. Other toggles (filters, radar, distance cap) do persist.

Can I use a different filter for different modes?

The passband is one value applied whenever the scanner tunes (it always sends mode + bandwidth together). Change RADIO_TUNE_MODE and RADIO_TUNE_BW as a pair, or set RADIO_TUNE_BW=0 and pick filters on the rig itself.

Where are all other controls documented?

See the full Help page — it covers the controls bar, beacon table, radar scope, rotator behaviour, status codes, troubleshooting and the API reference.
